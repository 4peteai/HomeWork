🔍 Debug Instructions - LLM Silent Issue

I've added extensive debug logging to help identify why Alex isn't responding. Follow these steps:

Step 1: Open Browser Developer Console

Chrome/Safari:

  • Press Cmd + Option + I (Mac) or F12 (Windows/Linux)
  • Or right-click anywhere on the page → "Inspect" → Click "Console" tab

Step 2: Clear Browser Cache

The browser may be caching old JavaScript files. Clear the cache:

  • Hard Reload: Press Cmd + Shift + R (Mac) or Ctrl + Shift + R (Windows/Linux)
  • Or in Chrome: Right-click the refresh button → "Empty Cache and Hard Reload"

Step 3: Load the Application

Navigate to: http://localhost:8000/scenario/friday-favor

You should see [DEBUG] messages in the console showing:

  • [DEBUG] loadPersona() started
  • [DEBUG] Scenario ID: friday-favor
  • [DEBUG] API response: {session_id: ...}
  • [DEBUG] addAlexMessageCard called with text: Hey. I'm literally about to head out...

Step 4: Try Sending a Message

Type a message and press Enter. Watch the console for:

  • [DEBUG] Chat response received: {alex_spoken_response: ...}
  • [DEBUG] About to call addAlexMessageCard with...
  • [DEBUG] Alex response message added

What to Look For

If you see [ERROR] messages:

  • Copy the full error message and share it with me

If you see [DEBUG] Timeline element: null:

  • The chat-timeline div is missing from the HTML

If debug logs stop at a certain point:

  • That indicates where the code is failing

If you don't see ANY debug logs:

  • The JavaScript file isn't loading or being cached
  • Try a different browser
  • Make sure the server is running: ps aux | grep uvicorn

Server Status Check

Verify the server is running:

cd ~/Desktop/difficult-conversations-multi-scenario
ps aux | grep uvicorn

If not running, start it:

cd ~/Desktop/difficult-conversations-multi-scenario
python3 -m uvicorn agent:app --host 0.0.0.0 --port 8000 --reload

Quick Backend Test

Test the backend directly (should work):

curl -X POST http://localhost:8000/api/start-scenario \
  -H "Content-Type: application/json" \
  -d '{"scenario_id":"friday-favor"}'

You should see JSON with session_id and opening_message.

After checking: Share what you see in the browser console - especially any [DEBUG] or [ERROR] messages, and I'll help identify the exact issue.
